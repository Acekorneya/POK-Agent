Harness changes

What changed in each run

BaselineSep 24

Stealth planner with JEV as System 1, memory on, no step cap. 154 tasks, 9 Chrome tasks could not be set up.

lo4Sep 26

Fixes from the baseline: spreadsheet navigation through the Name Box, working on the open document, LibreOffice's auto-update frozen.

lo5Sep 26

30-step cap from here on. System 1 types the keys and text the planner writes.

lo6Sep 26

OCR menu labels, popup reflex, keeping the app's own dialogs, foreground mode in the VMs, read-back after typing, hover, right-click and drag.

lo7Sep 26

The click tool accepts OCR text shown once, "replace" typing no longer wipes a sheet, malformed plans repaired.

lo8Sep 27

The planner sees OCR labels as targets; menu chains continue after the first click. Stopped at 30 of 43 when the perception gap was found.

v2Sep 27

Dialogs readable through UI Automation, LibreOffice 26.8 (full UI tree for System 1), hand-back training labels, memory shared across VMs like one agent. Full 154 tasks, two passes.

v3Sep 28

Skill replay by System 1 and lessons from failed tasks, seeded from v2's memory. Stopped at 59 of 154 when traces showed Windows 11 buttons were invisible to System 1.

Smoke 11–12Sep 28

Windows 11 control types, shortcut-suffix label matching, replay clicks only its saved labels, waits for a newly opened app, Defender exclusion in the test VM. 24 of 28 vs 22 in v2 pass 2.

v4Sep 28

Full 154 tasks from v2's memory with all of the above. Success level with v2 pass 2, System 1 more accurate, planner calls up 11%.

Smoke 15–18Sep 29

Motor programs: a verified run's exact clicks, keys and text are saved on its skill and replayed end to end; request text kept only as a fingerprint; commit shortcuts left to the planner. The harness takes the first look itself.

v5Sep 29

Full 154 tasks, two passes, on a golden image with Clock updated and OneDrive prompts off. Whole-program replays cut planner calls 28% (median 42%); partial replays cost calls. WAA scorer timeouts, a stuck-LibreOffice guard, and a memory-merge fix added along the way.

Nextafter v5

Only whole programs replay; similar requests replay with their own values filled into the recorded slots; programs saved only from runs whose result check passed at once. Then fine-tune Laya on the collected System 1 data.

Earlier planafter v4

Every System 1 result returns the new screen (re-looks after it were 67–91% without it), malformed plans repaired, longer typing sequences, and the planner told to send whole plans.

Caveats and data
  • The planner is an anonymous stealth model that varies run to run; differences of 2–3 tasks out of 43 are within that noise.
  • The baseline and lo4 had no step cap; every later run is capped at 30 acting steps.
  • v2 and later used LibreOffice 26.8 in the VM image; earlier runs used 24.8. WAA's checkers read the saved files, so scoring is unchanged.
  • v2 pass 1's System 1 figures in the LibreOffice charts cover both passes; later figures are per run.
  • v4 started from v2's final memory, so it is compared with v2 pass 2, which started from v2 pass 1's memory.
  • v3 was stopped at 59 of 154 tasks and is not charted. Smoke 11 lost 8 runs to Windows Defender blocking the agent in the test VM; its 8 tasks were rerun as smoke 12.
  • v5 started from v2's final memory, like v4; its pass 2 is compared with its pass 1 on the same tasks. Two Calc tasks in v5 pass 1 ran on a VM with a stuck LibreOffice process and scored 0.
  • LLM calls per task are means over tasks with recorded counts.
